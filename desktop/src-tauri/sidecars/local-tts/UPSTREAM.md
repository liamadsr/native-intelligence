# local-tts upstream

- **Upstream:** [VolgaGerm/PocketTTS.cpp](https://github.com/VolgaGerm/PocketTTS.cpp), a single-file C++ runtime for Kyutai's [Pocket TTS](https://github.com/kyutai-labs/pocket-tts) on ONNX Runtime. Git submodule `upstream/`; the commit the superproject records for it (`git ls-tree HEAD`) is the pin (`e801e7d6c2692121a39e80ae525cb5265174a495`, 2026-03-29, single maintainer). `build.sh release` fails if the checked-out submodule differs from that gitlink (debug warns); `SIDECAR_ALLOW_UNPINNED=1` turns the failure into a warning for a bump that has not been committed yet. Clone/update it with `GIT_LFS_SKIP_SMUDGE=1` (build.sh sets that and disables the LFS filters).
- **Our surface:** upstream's C API only (`ptt_*`). Upstream ships no header, so `src/pocket_tts_api.h` declares what we use, and CMake force-includes it into `pocket_tts.cpp`: a signature change in a bump is a compile error ("conflicting declaration of C function"), not a silent mismatch. We compile `pocket_tts.cpp` ourselves with `-DPTT_SHARED_LIB` (no CLI/HTTP `main`); upstream's own `CMakeLists.txt` is unused because it fetches unpinned dependencies (dr_libs `master`) at configure time.
- **Build:** `./build.sh <debug|release>` (both optimized) → `.out/bin/dial8-local-tts`, `.out/lib/libonnxruntime.1.23.2.dylib`, `.out/licenses/`, plus the dev tool `.out/tools/dial8-tts-make-voice` (never staged). Needs `cmake ≥ 3.26`, `ninja`, `python3`, `curl`. Cold build ~16 s on an M2 Max; a rerun with nothing changed is a no-op (stamps: `.out/deps/.stamp` for the pins plus a hash of the dependency recipe in build.sh (its helpers and step 2), so a changed build flag rebuilds them; `.out/src/.stamp` for upstream commit + patches; the voices source is rewritten only when `voices/` changes).
- **Portability:** arm64 only. Our code and SentencePiece target macOS 13.0 (`MACOSX_DEPLOYMENT_TARGET`). **Microsoft's ONNX Runtime dylib has `minos 13.4`** (`LC_BUILD_VERSION`, SDK 14.4), so the module needs macOS 13.4+: `module.json` says so (`"minMacos": "13.4"`) and the host shows it as unavailable below that (the app itself still runs). ld prints "built for newer version 13.4" when linking against it; that is expected and no longer filtered. `build.sh` step 5 reads `minMacos` and fails if any shipped Mach-O (`.out/bin`, `.out/lib`) has an `LC_BUILD_VERSION` minos above it, and if our binary's is not 13.0. Building our own ORT for 13.0 is the alternative if 13.0–13.3 matters.
- **Packaging:** `build.sh` walks `otool -L` from the binary and fails on anything outside `/usr/lib`, `/System` and our own `@rpath` dylibs. Result: `dial8-local-tts` → `@rpath/libonnxruntime.1.23.2.dylib` + libc++ + libSystem; ORT → system frameworks only. The binary's rpaths are `@executable_path/../Frameworks` (bundle) and `@executable_path/../lib` (dev). ORT's own `@loader_path` rpath is left alone, so its Microsoft signature stays intact until release.sh re-signs it. Sizes: binary 13.9 MB (13.0 MB of it the ten voice embeddings), ORT 34 MB.

## Long text

PocketTTS.cpp splits text only at `. ! ?` and, as written, stops each sentence at 500 frames (40 s) whether or not the model ended it (0005 caps it at tokens / 3 + 2 s, as upstream pocket-tts does). Past ~40 words in one piece the model starts dropping words, and by ~120 words (or a few hundred characters without a space) it runs to the cap, cut mid-word; unsplit, very long text can also overflow its context (an ORT `Reshape` error in the log). So `speak_one` splits each speak (`split_chunks`) into pieces of at most 30 words and 220 bytes, cutting at the last sentence end in the window, else the last `, ; :` or dash (at least 8 words in), else sharing the words out evenly; a run of over 220 bytes without a space is cut at a UTF-8 boundary. The pieces stream one after another under the speak's id: one `started`, the audio in order, one `done` with the total `audioSeconds`. Cancel is checked between pieces too. A piece with a sentence that runs to its frame cap without the model ending it (`ptt_last_stats`) is logged and `done` carries `"truncated": true`. `kMaxTextBytes` is 12,000 (the host caps a speak at 4,000 bytes before normalization, which can grow it ~2.5×); a frame over 1 MiB is read and dropped with a non-fatal `text_too_long` for its id, and the session goes on. Text the engine reduces to nothing (lone quotes, backticks: `speakable` mirrors upstream's `prepare_text`) is `done` with 0 s and never reaches the engine; speakable text that yields no audio is still `synthesis_failed`; `\u0000` is dropped by the JSON parser.

## Patches

Applied in order by `build.sh` to a pristine copy of upstream in `.out/src` (the submodule is never modified). A patch that doesn't apply fails the build; one that applies in reverse is already upstream (drop it). Each is a `git format-patch` with the explanation in its header, written to go upstream as is.

| Patch | Why | Upstream |
|---|---|---|
| `0001-bos-before-voice.patch` | Bundles from `english_2026-04` on (`bundle.json` `insert_bos_before_voice`) need `bos_before_voice.npy` prepended to the voice embedding; without it the output is noise. Also fixes `voice_hash()`, which hashed only the first 16 floats. With the BOS in front, those are the same for every voice, so a second voice would reuse the first one's KV snapshot. | to be proposed |
| `0002-fast-cancel.patch` | `ptt_stream_end` only took effect after the next decoded chunk (15 frames; one fp32 decode is ~100–140 ms on one thread). Now the generator checks a cancel flag every frame, and `interrupt()` sets ORT `RunOptions` terminate so in-flight runs return at once. The decode loop notices without waiting for a chunk. Adds `ptt_stream_cancel(ctx)` (any thread, non-blocking). The generator thread now catches exceptions (it used to `std::terminate`). Stop: ~123 ms → under 5 ms. | to be proposed |
| `0003-voice-embeddings.patch` | `ptt_add_voice(name, data, shape)` registers a voice from a precomputed embedding (no WAV, no encoder). `mimi_encoder.onnx` loads only when a WAV voice is first asked for. `ptt_encode_voice(encoder, clip, emb_path)` encodes a clip ahead of time, exactly as at runtime. Voice-conditioned KV snapshots are kept per voice in memory, and in-memory voices never touch the disk caches. | to be proposed |
| `0005-generation-options.patch` | Upstream pocket-tts changed generation after this port was written; each change is an option, off by default (`ptt_set_option`), and the sidecar turns them all on (`kGenerationDefaults` in main.cpp): EOS ignored on the first 6 frames (#319); a sentence capped at tokens / 3 + 2 s, not 40 s; the decoder fed every queued frame (#300), where it used to decode one frame and then wait for fifteen more, a ~0.3 s stall after the first 80 ms; a 5 ms fade-in at each sentence start, for the fresh decoder's click (#332); every sentence ending in `. ! ?` (a trailing `, ; : -` replaced, a period after `) ] %`; #296: without one the last word is often mispronounced or repeated). `ptt_last_stats` counts the last stream's sentences and those cut off at the cap. | to be proposed |
| `0004-decoder-precision.patch` | `precision` picked one suffix for every model. Config gains a path per model, plus `ptt_create_from_files(...)`, so the int8 `flow_lm_main`/`flow_lm_flow` load with the full-precision `mimi_decoder`. | to be proposed |

## Models (`module.json`)

`KevinAHM/pocket-tts-onnx` @ `58a6d00cf13d239b6748cb0769f35c580a8f606c`, `onnx/english_2026-04/`: `flow_lm_main_int8`, `flow_lm_flow_int8`, the full-precision `mimi_decoder`, `text_conditioner`, `tokenizer.model`, `bos_before_voice.npy`. 144.2 MB total, CC BY 4.0 (export by KevinAHM of Kyutai's `kyutai/pocket-tts` weights). The app downloads them; Dial8 doesn't redistribute them. `mimi_encoder.onnx` is **not** in the manifest and never ships: only `voices/make-voice.sh` uses it, on a developer Mac. Bump `assetsVersion` when an asset changes.

Settings: 2 threads, `lsdSteps` 8, int8 transformer + fp32 decoder (decided by listening, 2026-09-26); temperature 0.3 since 2026-10-16 (was PocketTTS.cpp's 0.7). 0.3 is what Kyutai ship this model at (`english_2026-04.yaml`), chosen in their human evals with a lower WER (pocket-tts #223). On our bench, 228 renders a setting, sentence endings came out wrong in 6 of 180 at 0.7 against 1 at 0.3, with steadier timing (duration spread 4.0% against 5.5% run to run) and the same pace (3.24 words/s). The 0005 options are on (`kGenerationDefaults`); `configure.options` overrides them by name, for the bench (the app sends none).

## Lead-in

The model opens every sentence with 0.2–0.45 s of digital silence (about -80 dBFS) before the first word. Between sentences it is the pause; when speech starts from silence it is only a wait. A `speak` with `trimLead` (the host sends it for the front of its queue, when nothing is playing) drops it from the first piece, keeping 40 ms before the first 20 ms window over -55 dBFS, at most 0.6 s. With the decoder fed every frame (0005) as well, the first word reaches the speaker about 0.14 s after the speak instead of 0.55 s (tana, 76 renders: 0.55 s → 0.32 s from 0005 → 0.14 s trimmed), with the same read-back word error and every first word intact.

## Words the model garbles

The host rewrites them after normalizing (`spoken_forms` in tts.rs), measured by reading renders back through local-stt: the "mm-hmm" family ("Mm-hmm", "Mhm", "Mmhmm" came out as "mamma", "mom" or nothing) becomes "Uh-huh", which is right every time; QoQ / YoY / MoM are spelled out ("QoQ" was read "CO two"); an all-caps acronym with a doubled letter and no vowel, and "ARR", is spaced ("LLM" was read "LM" 4 times in 6, "ARR" "AR"; spaced, 197 of 198 acronym renders right). Other acronyms read well as written (32 common ones: 190 of 198 right, every miss ARR or LLM) and stay. The web drops stage directions ("[laughs]" was read "loss"). Fillers the model says well: "Um,", "Uh,", "Oh,", "Ooh,", "Ah,", "Hmm,", "Haha," / "Ha ha," (the words, not a laugh), "Uh-huh,".

## Voices (`voices/`)

- `voices.json` is the catalogue; each `<id>.emb` holds an embedding (upstream's `.emb` format: `EMB1`, shape `[1, frames, 1024]`, float32, without the BOS). `build.sh` validates the catalogue (`voices/catalogue.py check`: ids, licence allow-list or consent, source and attribution, embedding shape and `embeddingSha256`) and compiles the catalogue plus every `.emb` into the binary (`.out/gen/voices_data.cpp`). `ready` lists the ids; the host can only pick one by id.
- The voices are Dial8's own, all Liam Alizadeh's own voice: **aba**, **cha** and **ush** (consent reference "Liam Alizadeh — own voice, recorded 2026-09-26"); **chichi**, **lori**, **lowli** and **tana** (the default since 2026-09-27; aba was until then), one take through four different effects (consent reference "Liam Alizadeh — own voice (effects), recorded 2026-09-26"); **milton** (consent reference "Liam Alizadeh — own voice, recorded 2026-09-27"); **nilo**, cut from an ElevenLabs render of Liam's ElevenLabs clone of his own voice (consent reference "Liam Alizadeh — own voice (ElevenLabs clone), 2026-10-22"); and **ava** (consent reference "Liam Alizadeh — own voice, recorded 2026-10-22"). The recordings stay private. Kyutai's four voices (alba, anna, marius, javert) were removed on 2026-09-26; the host maps any id the sidecar lacks, such as one a page saved earlier, to the default before it is sent (`resolve_voice`), since the sidecar answers an unknown id with `unknown_voice`.
- Making a voice: `voices/make-voice.sh <recording> <id> "<name>" --consent <ref> [--speech-dbfs N] [--replace]` (see its header). It refuses without `--consent`, unless the clip comes with `--licence` (+ `--attribution`, `--source`). It fetches the encoder (SHA-pinned, fp32 `mimi_encoder.onnx`, `853e2ca6…`) into `~/Library/Caches/dial8-local-tts/`, converts with `afconvert`, trims silence and levels the clip, then writes the `.emb` and the catalogue entry (`--replace` rebuilds one in place). Commit only those two; the recording and the consent stay private.
- Levelling: gain to the `--speech-dbfs` target (default -16), then a look-ahead limiter (5 ms look-ahead and attack, 80 ms release, 4× oversampled true-peak detector) holding peaks under -1 dBTP, with make-up until the speech sits on the target. The old plain peak cap (-20 dBFS speech, peaks under -3 dBFS) left peaky takes quiet. A voice renders at about its reference's speech level, from 2 dB under it to 1 dB over depending on the take, and replies should render at about -17 dBFS speech (Kyutai's alba, the old default). ## Bump

`scripts/modules/bump.sh local-tts <ref>` moves the submodule, runs `build.sh release` (patches must still apply), then `bench/bench.sh`. The bench needs the models (`TTS_MODELS=<dir>`, or read-aloud enabled in the app) and, for read-back, a built local-stt (`LOCAL_STT_SIDECAR`, or `../local-stt/.out/bin`) with its models. It drives the sidecar over protocol v1 like the app: warm-up; the chat set one `speak` at a time; 5 stops, each 300 ms after the first audio with a second utterance queued; unknown-voice and empty-text errors; stdin EOF mid-utterance. Then `bench/edge.py`: a 120-word sentence without commas and a sentence with 15 spelled-out amounts (split, normal pace, not truncated), a frame over 1 MiB and text over 12,000 bytes (non-fatal `text_too_long`, the sidecar keeps working), text of only quotes (`done`, 0 s), the shortest speakable text (`done` with audio), a NUL in the text, and nine cancels around the boundary between two pieces. Then it reads the chat-set clips back through local-stt.

**Gates** (2 threads, `lsdSteps` 8): first audio ≤ 60 ms median; ≥ 4× real time; every stop ≤ 100 ms with no audio after `cancelled`; read-back word error ≤ 3% on the chat set; clean exit on stdin EOF and after warm-up; every `edge.py` check passes. Still owed before beta: an M1 Air run (needs ≥ 3× real time).
